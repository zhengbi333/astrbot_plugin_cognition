# alpha-1.2.0

## 一、并行执行 `toolbox_parallel`

真实的活经常是"几件事互不依赖"（抓三个网站、处理三批文件、跑三种统计）。
以前只能一件件串行等；单个脚本里自己开线程又绕过了超时与输出治理。

现在给一层受控并发：

- 传一个 JSON 数组，每项含 `name` 与 `code`，最多几路同时跑（`parallel.max_concurrent`，默认 3，上限 6）；
- 每路**独立超时**（默认 60s，最大 300s）、独立输出上限；
- **单路失败不影响其它路**，结果按提交顺序返回，带各自状态、耗时、退出码；
- 脚本落在 `<工作区>/parallel/<批次>/` 下，事后可查。

实测证据：三段各睡 1.2 秒的脚本，三路并行总耗时 < 2.6 秒（串行会是 3.6 秒以上）；
并发设为 2 跑 4 路时总耗时 > 1.5 秒（证明排队生效）。

## 二、等任务 `toolbox_task_wait`

以前查后台任务要反复 `task_status`。现在可以一次等（默认 120s，最大 600s），
到点或结束后直接给状态与输出。

## 四、已知边界

- 并行只做**进程级**，不做"多轮对话/子代理"（那要额外的模型调用，另一套东西）；
- 每路的脚本是独立的，**不能共享内存**；要交换数据请经由工作区文件；
- 总输出会汇总，太长会按路截断（每路默认 400 字给模型）。
