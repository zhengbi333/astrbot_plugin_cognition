# alpha-1.5.13

## 第 6 条：空间点赞 + 评论

## 这条风险最高

| 动作 | 痕迹 | 风险 |
|---|---|---|
| `like_qzone` | 说说下面一个赞 | 轻 |
| `comment_qzone` | **文字出现在别人的说说下面** | **重 —— 公开可见，写错了收不回来** |

所以两个都是 **admin**，而且**都默认关**。评论那条我在 hint 里直接写了「**建议一直关**」。

## 一个 API 约束（差点做错）

`tid` 的参数说明是「来自 `get_qzone_msg_list`」——**不是** `get_qzone_feeds`。
也就是说，她得先拿到说说的 id 才能去互动。

改法：**让 `qq_qzone_feeds` 在返回里带出 tid**：

```
- [ABC123] 小明：今天考完试了
```

模型看到 tid，才可能调点赞/评论。没有这一步，两个工具都是废的。

## 缺参数一律拒绝，不瞎试

```python
if not tid:      return "缺说说 id（tid）。先调 qq_qzone_feeds 看动态..."
if not target:   return "缺 target_uin（那条说说所属的 QQ 号）。"
```

**宁可让模型去补参数，也不要拿空值去调接口** —— 空 tid 可能点到不存在的说说，
或者更糟，点到别人的东西。

## 超时处理（评论特殊）

- 点赞：40 秒
- 评论：**60 秒**，而且超时时明确说「**可能已经发出去了，也可能没发 —— 如实说不确定**」

评论没有幂等查询，超时后无法确认，只能如实。

## 验证（`audit_103_qzone_interact.py` 35/35）

- **A** 两个工具都在、调对 action、门禁键对；
- **B** **权限四档全验**：访客 False / **成员也 False** / 管理员 True（两个动作各 4 条）；
- **C** 配置：两个都**默认关**，comment 的 hint 里有「建议一直关」；
- **D** feeds 带出 tid；
- **E** **行为实测**：点赞成功且参数对、缺 tid 拒绝、缺 target_uin 拒绝、
  评论成功且参数对、超 60 字拒绝、空评论拒绝、调用失败如实说；
- **F** 超时：点赞 40s / 评论 60s / 评论超时提示「不确定」；
- **G** 语法。

## 已知边界

- 只支持**一级评论**，不支持「回复某条评论」（那要 `fid`，参数更复杂）；
- 评论内容不校验质量（模型可能写空话）—— 靠系统提示里的守则约束；
- `tid` 依赖 feeds 返回里带这个字段。如果 SnowLuma 某个版本不返回 tid，
  这两个工具会一直提示「缺 tid」，属于**安全失败**（不会误点）。
