# alpha-1.5.11

## 第 4 条：发说说 `qq_qzone_post`

## 借鉴 Aurabot 修正两处（其中一处是致命的）

看了 `dsh-aurabot-qq/src/features/qzone.js`，发现两个问题：

### ① 权限常量我写错了

Aurabot 的常量表是 `{ all: 1, friends: 4, self: 64 }`。
我原来在 hint 里写「16 / 128 = 指定好友或分组可见」——错的。正确是 **friends = 4**。已改正。

### ② 空间接口必须给 60 秒超时（致命）

```js
await onebot.call('send_qzone_msg', {...}, { timeoutMs: 60000 })
```

我的 `call_action` 没设超时，走 AstrBot 默认值（十几秒）。
空间接口走腾讯网页 API，要上传、要过鉴权，必然会超时失败。

现在：
- 探测 `get_qzone_public_capabilities`：25 秒
- 发送 `send_qzone_msg`：60 秒
- 超时单独处理：发说说超时时如实说「不确定是否发出」（它可能真的发出去了）

## 安全设计

| 项 | 值 | 为什么 |
|---|---|---|
| 权限 | admin | 只有主人能让她发 |
| 默认开关 | 关 | 空间接口有风控 |
| 默认可见范围 | 64（仅自己可见） | 当日记写最安全 |

## 发之前先探测

账号没空间能力（登录态失效、新号风控）就如实说，不假装发出去。

## 验证（`audit_101_qzone_post.py` 30/30）

- 五件套齐 + 先探测后发布（顺序断言）+ 200 字上限；
- 权限三档：访客 False / 成员 False / 管理员 True；
- 配置：默认关、默认 64、hint 说清含义；
- **行为实测**：探测失败时只调了探测、没调发布（不假装发出）；空内容/超长被拒。

## 已知边界

- 图片配图没做（Aurabot 用 base64 传图）；
- **没有定时策略** —— Aurabot 有 `planDiaryTimes`（每天 N 次、时间窗内随机），
  那才是真的「有自己的生活」。我们现在还是模型临时起意；
- 超时后无法确认是否真的发出（腾讯接口没幂等查询）。
