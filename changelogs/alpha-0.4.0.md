# alpha-0.4.0

## 一句话

从「固定菜单」变成「**能自己写代码解决没预料到的情况**」——这是"任意任务"与"几个功能"的分水岭。

## 为什么加这个

工具是有限的，任务是无穷的。用户要的"帮我做个 xxx"绝大多数并不需要新工具，
而是需要一个**能当场写代码的出口**：

- 批量改名 / 转换格式 / 合并多份文档；
- 统计与筛选表格、算日期、算账；
- 生成图表、生成 pptx/xlsx；
- 抓一批数据再清洗；
- 任何不在菜单里的活。

装了这些库（AstrBot 自带）：`pandas`、`numpy`、`python-docx`、`openpyxl`、`python-pptx`、`Pillow`。

## 怎么做的

`toolbox_python(code, timeout=30)`：

1. 代码写入 `workspace/.tmp/run_<指纹>.py`（工作区锁死，相对路径都在里面）；
2. 用**当前 AstrBot 的 Python 解释器**执行（所以库都在），`PYTHONUTF8=1`；
3. stdout+stderr 合并返回，超过 `exec.max_output_chars`（默认 4000）截断；
4. 超时强杀（默认 30s，上限 120s）；
5. **每次执行记入审计**（代码指纹 + 首行），事后可查。

## 安全边界（这是重点，请读完）

- **只允许 `exec.owner_ids` 名单里的账号触发**，默认就是使用者本人；
  **名单留空 = 谁都不能用**，绝不等于"所有人能用"。群友调用会被直接拒绝并记审计。
- 脚本只能通过**相对路径**落在工作区里；但它运行在 Python 进程里，
  **技术上可以读写整台机器** —— 这是"任意任务能力"的固有代价，所以它只给主人。
- 有超时、输出上限、代码长度上限（默认 20000 字符）。

## 验证

`_st_test/test_cognition_unit.py` —— **112/112**（0.3.0 的 94 项 + 新增 18 项）：

| 断言 | 覆盖 |
|---|---|
| O1–O5 | owner 名单解析（中英文逗号/分号）、空名单拒绝、名单内外判定、代码指纹稳定、首行提取跳过注释 |
| O6 | **真跑**：`print(1+1)` → 输出 `2` |
| O7–O8 | **真产出**：脚本用 openpyxl 生成 `out/stat.xlsx` → 文件存在且能被 `read_xlsx` 读回 |
| O9 | pandas 可用（`DataFrame.sum()` → 3） |
| O10 | 输出超限截断 |
| O11–O13 | 超时强杀、空代码拒绝、代码过长拒绝 |
| O14–O18 | 接线：注册、非 owner 拒绝、受 `exec.enabled` 约束、schema 默认 owner / 超时 |

其中 O7 第一次跑**失败**了：测试脚本自己忘了建 `out/` 目录，而错误原文被完整回传
（`FileNotFoundError ... 'out/stat.xlsx'`）——这恰好验证了"报错如实回传、模型能据此改一版"这条设计。

## 已知边界

- 没有沙箱：脚本拥有主人的权限。只给主人用是**唯一**的现实约束。
- 不做虚拟环境隔离；装什么库就是什么库。
- 长时间任务（>120s）会被杀，暂不支持后台作业。
