# alpha-0.8.0

## 一、新增 QQ 平台社交动作

参考项目里有一类"QQ 特有动作"，和我们现有的通用工具是两码事：失败原因不同
（平台不支持 / 权限不足 / 频率限制），安全模型也不同。本版补两个：

| 工具 | 作用 | 平台动作 |
|---|---|---|
| `toolbox_poke` | 戳一戳 / 拍一拍 | 群聊 `group_poke(group_id, user_id)`、私聊 `send_poke(user_id)` |
| `toolbox_like` | 给名片点赞 | `send_like(user_id, times)` |

实现走 `event.bot.call_action(...)`（aiocqhttp 的 CQHttp 通用动作通道），
所以不依赖框架是否包了高层方法；非 aiocqhttp 平台会明确回"当前平台不支持这个动作"。

### 目标约束（比"填个 QQ 号"严得多）

- **默认目标 = 当前说话的人**（戳回去 / 给他点个赞），这是最不容易被滥用的语义；
- 允许显式指定，但**只接受"说话人本人"或"机器人自己"**；
- 想戳无关的人？直接拒绝。即使有人诱导也打不出去。

### 配额

- 戳一戳与点赞**各自**每天有上限（`actions.daily_limit`，默认 20，0=不限）；
- 单次点赞数收敛到 `actions.like_cap`（默认 10）；
- 计数只保留当天键，不会无限增长。

## 二、暂时做不到的（说清楚，不装作做了）

**QQ 说说（Qzone）**：发说说 / 看说说 / 赞说说 / 评论 / 改权限，这一整族动作
**不在标准 OneBot v11 协议里** —— 它们属于 SnowLuma 的扩展 API。
AstrBot 的 aiocqhttp 适配器只走标准协议，所以**我们做不到**，除非绕过框架直连 SnowLuma
（那会引入一个新服务依赖与一套新鉴权，超出本插件边界，不做）。

## 三、验证

`_st_test/audit_66_qq_actions.py` —— **24/24**：

- 群聊/私聊路由正确（`group_poke` vs `send_poke`，参数形态正确）；
- **目标约束**：拒绝第三方、允许机器人自己、拿不到说话人时拒绝；
- 点赞次数上下限收敛；
- 平台报错转成可读文案（含原因）；
- `describe_event_kind` 能识别 `notice_type/sub_type=poke` 与文本里的「戳一戳」，普通消息不误判；
- 接线与 schema 默认值。

## 四、已知边界

- **"被戳"目前只做了识别能力**（`describe_event_kind`），还没有接进人格的"要不要回应"判定 ——
  需要先在真机确认 AstrBot 把 poke 事件转成消息事件后的**文本形态**，再决定怎么接。
- 点赞/戳一戳的**实际效果**依赖协议端（NapCat/SnowLuma）是否实现对应动作，失败会如实回报。
