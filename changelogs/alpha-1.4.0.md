# alpha-1.4.0

## 一、子代理升级：从「一次默认调用」到「多专家」

对标 AstrBot 的 `SubAgentOrchestrator`（handoff 模式），但**不接它**——
它的 handoff 挂在主链的 `FunctionToolManager` 上，我们的插件是独立链路，
硬接要依赖它的内部 API（而且它自己标着"实验性"）。所以按它的设计自己做，并补上它没有的东西。

### 做了什么

| 能力 | 说明 |
|---|---|
| **多专家** | `delegate.agents` 配 JSON 数组：`name` / `description`（给主模型看的一句话）/ `system` / `provider_id` / `max_chars` |
| **按名字选派** | `toolbox_delegate(agent="审稿", task=..., material=...)`，支持前缀匹配（「审稿」命中「审稿人」） |
| **专家清单** | `toolbox_delegate_list`：列出专家 + 今日剩余额度 |
| **per-agent provider** | 每个专家可指定 `provider_id`，便宜活交给便宜模型（这是 AstrBot 那套最值钱的一点） |
| **日调用上限** | `delegate.daily_limit` 默认 30，用完拒绝，明天重置（AstrBot 没有成本护栏） |
| **审计** | 每次调用都 `_note_call`（成功/失败/未知专家/额度耗尽都记） |

### 关键设计：主代理取数，子代理思考

- 她（主链路）有 32 个工具 → 负责把材料找来（读文件、抓网页、查记忆）；
- 子代理**不给工具** → 只在干净上下文里想，想完交回结论。

这样既躲开"子代理再调一轮工具"的复杂度，也避免它乱动工作区。工具描述里明确写了这条分工，
教模型别把"需要动手"的活丢给子代理。

### 和 AstrBot handoff 的差别

| | AstrBot handoff | 我们 |
|---|---|---|
| 触发 | 注册成工具，主链自动可见 | 显式 `toolbox_delegate(agent=...)` |
| 子代理工具 | 可配工具集 | 不给（主代理取数） |
| 成本护栏 | 无 | 材料 4000 / 输出按专家 / 日 30 次 |
| 审计 | 框架日志 | `_note_call` |

## 二、配置示例

```json
[
  {"name": "审稿", "description": "挑出文档里的问题，按严重程度列",
   "system": "你是严格的审稿人，只挑问题，不夸。按严重程度排序，每条给一句修改建议。",
   "max_chars": 1200},
  {"name": "翻译", "description": "中译英，自然口语",
   "system": "你是技术翻译，把中文译成自然英文，保留术语原样。",
   "provider_id": "便宜模型ID"}
]
```

## 三、验证

`_st_test/audit_75_experts.py` —— **37/37**：

- 专家解析 11 项（跳过无名、system/max_chars/provider_id、空串、非法 JSON、单对象、夹紧、手写反斜杠）；
- 查找 6 项（精确/大小写/前缀/找不到/空名/一行格式）；
- 日预算 4 项；
- 调用隔离 9 项（专家 system 生效、结果带专家名、按专家上限截断、默认系统提示、空任务/无 provider/异常/空回复）；
- 接线 7 项。

## 四、已知边界

- 子代理**没有工具**（这是设计选择，不是遗漏）；
- 只跑一次、无多轮自我修正（要改就让主链再交一次）；
- 日额度存在进程内存里，重启清零（可以接受：这是护栏不是账本）；
- 不并发：一次一个（并发子代理会让成本不可控）。
